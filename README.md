# 과제 - 05: 순차 탐색과 이진 탐색 트리 탐색의 비교

## 1. 과제 개요

0부터 1,000 사이의 서로 다른 정수 100개를 임의로 생성하여
정수 배열과 이진 탐색 트리에 저장하였다.

배열에서는 순차 탐색을 수행하고,
이진 탐색 트리에서는 BST 탐색을 수행하였다.

각 탐색에서 발생하는 숫자 비교 횟수를 측정하고,
BST를 생성하는 과정에서 발생하는 비교 횟수도 함께 측정하였다.

---

## 2. 데이터 저장

100개의 정수는 생성된 순서 그대로 배열에 저장하였다.
배열은 정렬하지 않았다.

동일한 값이 생성되는 경우에는 다시 난수를 생성하여
서로 다른 100개의 값을 저장하였다.

같은 100개의 데이터를 생성 순서대로 BST에 삽입하였다.

BST는 포인터를 이용한 연결 자료구조로 구현하였다.

각 노드는 다음 정보를 가진다.

- 정수 데이터
- 왼쪽 자식 포인터
- 오른쪽 자식 포인터

---

## 3. 탐색 방법

### Sequential Search

배열의 첫 번째 원소부터 마지막 원소까지 순서대로 비교하였다.

탐색 대상과 배열의 값이 같으면 탐색을 종료하고,
끝까지 찾지 못하면 탐색 실패로 처리하였다.

각 원소와 비교할 때마다 비교 횟수를 1 증가시켰다.

### BST Search

BST의 루트 노드부터 탐색을 시작하였다.

탐색 대상이 현재 노드보다 작으면 왼쪽으로 이동하고,
크면 오른쪽으로 이동하였다.

현재 노드의 값과 탐색 대상이 같으면 탐색에 성공한다.

각 노드의 값과 비교할 때마다 비교 횟수를 1 증가시켰다.

---

## 4. 실험 결과

실행 결과는 다음 항목을 확인할 수 있다.

- 100개의 생성 데이터
- BST 생성 비교 횟수
- 50개의 Search Key
- 각 Search Key의 탐색 결과
- Sequential Search 비교 횟수
- BST Search 비교 횟수
- Sequential Search 총 비교 횟수
- Sequential Search 평균 비교 횟수
- BST Search 총 비교 횟수
- BST Search 평균 비교 횟수
- BST 생성 비용

실행할 때마다 난수를 새로 생성하기 때문에
비교 횟수는 실행할 때마다 달라질 수 있다.

---

## 5. 성능 분석

순차 탐색은 배열의 처음부터 탐색하기 때문에
탐색 대상이 앞부분에 있으면 비교 횟수가 적지만,
뒤쪽에 있거나 존재하지 않는 경우에는 많은 비교가 필요하다.

100개의 데이터를 대상으로 하는 순차 탐색의 경우
최악의 경우 100번의 비교가 필요하다.

반면 BST 탐색은 현재 노드와의 비교 결과에 따라
왼쪽 또는 오른쪽의 한쪽 방향으로 이동하기 때문에
일반적으로 순차 탐색보다 적은 비교 횟수로 탐색할 수 있다.

BST가 균형에 가까운 구조를 가지면 탐색 비용은
대략 O(log n)의 특성을 보인다.

그러나 BST의 구조가 한쪽으로 치우치면
탐색 성능이 나빠질 수 있다.

최악의 경우 BST가 연결 리스트와 비슷한 구조가 되며,
탐색 비용은 O(n)까지 증가할 수 있다.

---

## 6. BST 생성 비용 고려

순차 탐색은 배열에 데이터를 저장할 때 별도의
탐색 구조를 만들기 위한 비교가 필요하지 않다.

반면 BST는 데이터를 삽입할 때마다
현재 노드와 값을 비교하여 새로운 노드를 삽입할 위치를 결정해야 한다.

따라서 BST의 성능을 비교할 때 탐색 과정의 비교 횟수만
비교하는 것은 충분하지 않다.

본 실험에서는 BST 생성 과정에서 발생한 비교 횟수를
별도로 측정하였다.

최종적으로 다음과 같이 비교할 수 있다.

Sequential Search 전체 비용
= 50회 탐색의 비교 횟수

BST 전체 비용
= BST 생성 비교 횟수 + 50회 BST 탐색 비교 횟수

따라서 탐색을 적은 횟수만 수행한다면
BST를 생성하는 비용 때문에 순차 탐색이 더 유리할 수도 있다.

반대로 같은 BST를 이용하여 많은 탐색을 반복한다면
BST 생성 비용을 여러 번의 탐색에 분산할 수 있기 때문에
BST 탐색이 더 효율적일 가능성이 높다.

---

## 7. 결론

이번 실험에서는 동일한 100개의 데이터를 이용하여
순차 탐색과 BST 탐색의 비교 횟수를 측정하였다.

순차 탐색은 구현이 간단하고 별도의 자료구조 생성 비용이
필요하지 않다는 장점이 있다.

BST 탐색은 데이터를 저장하는 과정에서 추가적인 비교 비용이
발생하지만, BST가 균형에 가까운 구조라면 탐색 과정에서
필요한 비교 횟수를 크게 줄일 수 있다.

따라서 탐색 횟수가 적은 경우에는 순차 탐색이 유리할 수 있고,
많은 데이터를 반복적으로 탐색해야 하는 경우에는
BST를 구성한 후 탐색하는 방법이 더 효율적일 수 있다.

또한 BST의 성능은 트리의 구조에 크게 영향을 받는다.
균형 잡힌 BST에서는 탐색 성능이 좋지만,
한쪽으로 치우친 BST에서는 탐색 성능이 크게 저하될 수 있다.
